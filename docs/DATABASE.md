# Database design

54 tables + 11 views. Schema source of truth: `db/schema.js` (Drizzle). Migrations: `db/migrations/`.

Conventions: text (uuid) PKs generated by the app (old-app keys like `q-aa`, `pa-10` are kept where they are
stable); `numeric(18,4)` money/qty, `numeric(18,6)` ratios; `varchar + CHECK` instead of enums; JSON in `text`.
**`extra`** columns hold JSON for anything the UI document has that doesn't fit a typed column, plus `__keys`
(original key order) so `repo.getProject()` returns the exact original JSON (lossless round-trip; tested).
**Soft delete** (`deleted_at`, `deleted_by`) on business tables; reads and views filter it. Rows that are parts
of a project document (sections, lines, cost items, open items...) are instead *replaced* on each save
(history = `activity_log` before/after JSON + `bid_snapshots`).

## MASTER (company-wide)

| table | purpose |
|---|---|
| roles | app roles: admin, estimator, viewer |
| users | logins; `role_id`, `employee_id` (link to person), `last_login_at` |
| app_settings | key/value JSON (library defaults: tax %, hours/day, t/CY, company block) |
| regions | markets: TX-HEB, FL-SWFL, FDOT-MA10 |
| companies | WPM itself (`self`), clients, GCs, owners, competitors, agencies |
| contacts | people at companies |
| vendors | material/trucking/sub/equipment vendors (optionally a company) |
| employees | WPM staff (employee_no, names, title_role, dept, contact, hire_date, status, labor class, emergency contact, yard, HR id) |
| employee_certifications | OSHA/CDL/etc. with `expires_on` (indexed) |
| labor_classes | labor classes with wage/burden + effective dates |
| equipment_catalog | equipment with hourly rate, owned/rented, effective dates |
| materials_catalog | materials with default price/vendor |
| cost_codes | generic civil divisions (01 General Conditions ... 15 Survey & Testing) |
| crews | named crews with $/hr labor + equipment (HEB crews) |
| crew_resources | costing makeup of a crew (labor classes / equipment x qty) |
| crew_members | which employees are on which crew (role, effective dates) |
| rate_libraries | named production-rate libraries (source, region) |
| rate_library_versions | versions with effective dates, region, source, `is_current` |
| production_rates | rates per version: `rate_key` (app id, e.g. `pa-10`), units/day, $/hr, HEB activity |
| vendor_quotes | material/sub quotes: quote_no, date, expiry, tax, completeness, owner (employee) |
| vendor_quote_lines | quote line items: unit price, ext, scope key, complete, tax exempt |
| sub_quotes / sub_quote_lines | lump-sum subcontractor quotes (same layout) |
| fdot_reference_prices | FDOT historical prices (statewide 6-mo, Market Area 10 12-mo) |
| exclusion_templates | standard proposal exclusions (13) |
| note_templates | standard proposal notes (3) |
| stored_files | file bytes (`storage_kind=db`, bytea) or object-storage key (`s3`), sha256, mime, size |
| activity_log | append-only audit of every write (trigger rejects UPDATE/DELETE/TRUNCATE) |

| table | purpose |

| project_assignments | employee x project x role (estimator, pm, superintendent...) with dates |

| bid_competitors | other bidders and their amounts |

| assumptions | estimating assumptions |

## Earthwork studio (migration 0002)

The static Earthwork Takeoff Studio keeps its grids, aerials and grading plans in `stored_files` and hangs normalized quantities off a project. One project can have several `ew_versions` (Alamo base and alternate; Innovation phases 2–3, phase 2, and phase 3). File numbers are stored only when the job JSON states them (`source = file_reference`). A save from the page adds `source = computed` rows and, once someone edits the example rates and asks for a snapshot, a `bid_snapshots.earthwork_json` freeze. Dollars stay null until that happens.

| table | purpose |
|---|---|
| ew_versions | one grid / scenario: strip, shrink, swell, subgrade inputs, rev, file ids, editor JSON |
| ew_areas | area name, type, section depth (subgrade), moisture, finish elevation |
| ew_balance | cut, fill, import, export, shrink, swell, by site or phase |
| ew_grading | per-area grading result from a studio compute |
| studio_rates | company equipment and crew card the page edits (not the HEB library) |
| studio_bids | per-scenario quantity, trucking and material worksheet |
| user_sessions | sha256 of the login cookie |

View `v_ew_balance` is reportable through `repo.report`. Soft delete on the version hides it; `repo.restore` brings it back. Child rows replaced on import follow the same pattern as line items: the activity log holds the change.
