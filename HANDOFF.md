# Takeoff Studio database package - handoff

The Earthwork Takeoff Studio now serves this package from `server/` (see README.md). The database layer below is unchanged in its rules: all writes go through `db/repo.js`, and the Buc-ee's sample still ties to $18,405,662.10.

A standalone, framework-agnostic database layer for WPM Civil's Takeoff Studio: Drizzle schema + SQL migrations,
a central data layer (`db/repo.js`) that writes an append-only activity log for every change, an idempotent
seed (company library + Buc-ee's #49 sample), import CLIs, reporting views, and tests. No web UI, no server.

## Files

| path | what |
|---|---|
| `db/schema.js` | Drizzle pg-core schema (54 tables), value lists for CHECK constraints |
| `db/migrations/0000_init.sql` | portable DDL generated by drizzle-kit from schema.js |
| `db/migrations/0001_pg_specific.sql` | **only** Postgres-specific objects: activity_log append-only trigger + 11 reporting views |
| `db/migrations/meta/` | drizzle-kit journal/snapshots (needed by `db:generate` and the migrator) |
| `drizzle.config.js` | drizzle-kit config |
| `db/client.js` | provider switch: `pg` Pool (DATABASE_URL) or PGlite (local) -> `openDb()` |
| `db/migrate.js` | `npm run db:migrate` (drizzle migrator, works for both providers) |
| `db/context.js` | `runWithContext({ user_id, employee_id, request_id }, fn)` (AsyncLocalStorage) |
| `db/repo.js` | **the** data layer. All writes go through it; each write + its activity_log row = one transaction |
| `db/mapping.js` | lossless JSON<->row mapping (typed columns + `extra` JSON for the rest) |
| `db/calc.js` | old app pricing math (copy of `seed-data/calc.reference.js`) used to fill computed cost columns |
| `db/seed.js` | `npm run db:seed` - idempotent seed |
| `db/import-project.js` | `npm run db:import-project -- <file.json>...` - import old per-job JSON files |
| `db/import-employees.js` | HR CSV upsert stub (docs/HR_IMPORT.md) |
| `db/import-job-costs.js` | job-cost CSV import stub |
| `db/reset.js` | `npm run db:reset` - local only (refuses non-localhost DATABASE_URL) |
| `db/csv.js` | tiny CSV parser |
| `db/seed-data/` | `library.json`, `bucees-49.project.json`, `calc.reference.js` (inputs) |
| `test/*.test.js`, `test/fixtures/` | node:test suites (PGlite in-memory / temp dir) |
| `docs/DATABASE.md` | master vs project split, one line per table, ER diagram |
| `docs/SQL_SERVER.md` | SQL Server equivalents (types, trigger, views, REVOKE/DENY) |
| `docs/HR_IMPORT.md` | HR CSV format and rules |

## Install / migrate / seed / test

```bash
npm install
npm run db:migrate          # creates ./.pglite (embedded Postgres) when DATABASE_URL is unset
npm run db:seed             # runs migrations too; safe to re-run
npm test                    # in-memory PGlite; never touches DATABASE_URL
npm run db:reset            # local only: wipe + migrate + seed
npm run db:generate         # after editing db/schema.js -> writes the next migration SQL
```

## Provider switch (`db/client.js`)

| env | effect |
|---|---|
| `DATABASE_URL` set | `pg` Pool. Format (Render): `postgresql://USER:PASS@HOST:5432/DB` |
| `DATABASE_SSL` | SSL **on** by default with `rejectUnauthorized:false`; `DATABASE_SSL=false` disables (local Postgres) |
| `DB_POOL_MAX` | pool size, default 5 |
| `DATABASE_URL` unset | PGlite at `PGLITE_DIR` (default `./.pglite`); `PGLITE_DIR=memory` = in-memory |

`.env.example` has placeholders only. Never commit `.env`.

## Render

1. Render dashboard -> **New -> PostgreSQL**. Create the database (same region as the web service).
2. On the database page copy:
   - **Internal Database URL** -> use as `DATABASE_URL` for Render services (web service env var).
   - **External Database URL** -> use from your laptop (SSL required; the client enables SSL by default).
3. Set `DATABASE_URL` on the web service (Environment tab). Do not put it in git.
4. Run once (Render shell, a pre-deploy command, or locally with the External URL):
   ```bash
   npm run db:migrate && npm run db:seed
   ```
   Use `npm run db:migrate` as the **pre-deploy command** so new migrations apply on each deploy.
5. Optional hardening: run the `REVOKE UPDATE, DELETE, TRUNCATE ON activity_log` SQL in docs/SQL_SERVER.md
   for the role the app connects as.

## Using it from xlr8clay/takeoff-studio (static `index.html` + per-job JSON)

Browsers cannot talk to Postgres, so the static app needs a **small API server** (Express/Fastify/etc., e.g. a
Render web service) that imports this package:

```js
const { openDb } = require('./db/client');
const { createRepo } = require('./db/repo');
const { runWithContext } = require('./db/context');
const repo = createRepo(await openDb());

app.use((req, res, next) => runWithContext({ user_id: req.user?.id, employee_id: req.user?.employee_id,
  request_id: req.get('x-request-id') }, next));
app.get('/api/projects', async (req, res) => res.json(await repo.listProjects()));
app.get('/api/projects/:id', async (req, res) => res.json(await repo.getProject(req.params.id)));   // old JSON shape
app.put('/api/projects/:id', async (req, res) => {
  try { res.json(await repo.saveProject(req.body)); }                                            // body.rev = rev you loaded
  catch (e) { res.status(e.status || 500).json({ code: e.code, message: e.message }); }           // REV_CONFLICT -> 409
});
app.get('/api/library', async (req, res) => res.json(await repo.getLibrary()));                  // old library.json shape
```

The UI keeps working with the same JSON documents: `getProject` returns exactly the shape the app already saves
(unknown/new fields are preserved in `extra` columns), and `saveProject` takes it back. On a 409 the UI should
reload the project and re-apply the user's edit.

**Migrating existing per-job JSON files:**
```bash
npm run db:import-project -- path/to/jobs/*.json --estimator emp-clay --region FL-SWFL
```
New ids are created (rev 1); ids already in the DB are overwritten as a new rev (previous version stays in
`activity_log.before_json`). After import, call `repo.snapshotRates(id)` / `repo.createBidSnapshot(id)` /
`repo.recordBidOutcome(id, {...})` as bids are submitted and decided.

## repo.js API (summary)

- Generic: `insert(table, values)`, `update(table, id, patch)`, `softDelete(table, id)`, `restore(table, id)`, `get`, `list`
- Projects: `createProject(doc, {estimatorId, regionCode, status})`, `saveProject(doc, {expectedRev})` (REV_CONFLICT 409),
  `importProject`, `getProject`, `listProjects`, `setProjectStatus`, `softDeleteProject`, `restoreProject`, `assignEmployee`
- Bids: `snapshotRates`, `createBidSnapshot`, `recordBidOutcome` (copies totals from the snapshot, moves project status), `linkQuoteToProject`
- Files: `storeFile({filename, mime, bytes | object_key})`, `getFile`, `recordExport`, `recordAiRun`, `updateAiRun`
- People/cost: `upsertEmployee`, `addCertification`, `addCrewMember`, `addJobCostActual`, `recordLogin`
- Library: `getLibrary`, `listLibrary(kind)`, `getLibraryItem`, `upsertLibraryItem`, `updateLibraryItem`, `deleteLibraryItem`, `setSetting` (kinds: rates, crews, quotes, fdot)
- Reports: `report(viewName, filters, {orderBy, desc, limit})` (whitelisted views; filters `{col: value}` or `{col: {op, value}}`), `activity({project_id, ...})`

## Notes / limits

- PGlite is single-connection; fine for local dev/tests. Production uses `pg`.
- `stored_files.bytes` is fine for proposals/exports; large plan PDFs should use `storage_kind='s3'` + `object_key`.
- `clientForm`, `sampleTieOut`, timestamps and any unknown fields of a project document live in `projects.extra`.
- Project status values: lead, bidding, submitted, won, lost, no_bid, cancelled. Outcome -> status mapping:
  pending->submitted, won->won, lost->lost, not_awarded->cancelled, withdrawn->no_bid.
